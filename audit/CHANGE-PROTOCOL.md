# بروتوكول التغيير والتسليم

يطبق على كل مبرمج أو مساعد ذكاء اصطناعي يعمل على NOKTA POS.

1. اقرأ `AGENTS.md` و`PROJECT-HANDOFF.md` و`audit/REPAIR-LOG.md` و`ARCHITECTURE-PLAN.md` وآخر إدخال في `audit/CHANGELOG.md`.
2. افحص حالة Git ولا تكتب فوق تغييرات غيرك.
3. حدد وحدة تجارية واحدة للدفعة. إذا تغيرت أكثر من وحدة، اشرح سبب عدم إمكان فصلها.
4. اكتب أو حدّث الاختبار الذي يثبت السلوك قبل نقل الكود.
5. نفذ أصغر تغيير يحافظ على العقود الحالية.
6. شغّل الاختبار المحدد، ثم `pnpm test`، ثم `pnpm run check`، وسجل النتيجة الفعلية بلا تجميل.
7. لأي نص ظاهر، أضف مفاتيح العربية والإنجليزية واختبار الترجمة.
8. لأي schema، أضف migration متوافقة واختبار ترقية من قاعدة قديمة.
9. عند تعديل الواجهة، حدّث إصدار أصول PWA واختبر التحميل بعد تحديث Service Worker.
10. قبل إنهاء الدفعة، أضف إدخالًا كاملًا في `audit/CHANGELOG.md` وحدّث `PROJECT-HANDOFF.md` إذا تغيرت نقطة البداية أو الثوابت.

إذا تعذر اختبار شيء، لا تكتب أنه نجح. سجّل السبب والخطر والخطوة المطلوبة للتحقق منه.
